# 091 — tox module Phase 1: repeat-dose ingest vertical slice

**Date:** 2026-08-19
**Agent:** tox-dev-p1

## What was implemented

Phase 1 vertical slice for the `venter tox` module, proving the module
structure end-to-end with one schema validated, one artifact written, one
sidecar constructed, and all registration points wired.

### Deliverables

1. **`tools/venter/commands/tox.py`** — new module containing:
   - Click group `tox` for future subcommand additions (genotox, margins, analyze)
   - `tox ingest` subcommand handling `venter.tox-repeat-dose.v1` schema
   - Exhaustive `_validate_repeat_dose` validation covering all required fields,
     types, value sets, and cross-field constraints (NOAEL must match a dose group,
     LOAEL > NOAEL, noael_exposure requires at least auc or cmax)
   - Full constant sets for all planned schemas (repeat-dose, safety-pharm, genotox)
   - `_sanitize_id` helper preventing path traversal
   - Sidecar construction with 6 provenance notes plus non-standard species warning
   - Emitter pattern following pk.py conventions

2. **`tools/venter/core/context.py`** — registered `ARTIFACT_DIRS["tox"] = "raw/tox"`

3. **`tools/venter/cli.py`** — registered `tox` command before `enforce_phase_two(cli)`

### Design decisions

- **Species acceptance:** any non-empty string is accepted (supporting less common
  model organisms), but non-standard species trigger a sidecar warning for review.
- **Schema dispatch:** ingest checks the schema tag before dispatching to the
  validator. Unimplemented schemas (safety-pharm, genotox) raise Refusal with a
  "future release" message rather than silently failing.
- **glp_status default:** normalised to `"not_stated"` when absent from input.
- **Validation helpers extracted:** `_validate_finding` and `_validate_noael_exposure`
  are separate functions for readability given the nested structure of the schema.

### What was not run

- Full CLI integration test could not be run (click not installed in this environment).
- Syntax verification passed via `ast.parse`.
