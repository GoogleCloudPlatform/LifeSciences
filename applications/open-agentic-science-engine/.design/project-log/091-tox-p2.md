# Project Log: tox Phase 2 — safety-pharm and genotox ingest (#91)

**Agent:** tox-dev-p2
**Date:** 2026-08-19
**Branch:** `scion/tox-p2`
**Depends on:** Phase 1 (`scion/tox-p1`)

## Summary

Extended `tox ingest` to handle all three tox schemas via schema-tag dispatch.
Phase 1 handled only `venter.tox-repeat-dose.v1`; this phase adds
`venter.tox-safety-pharm.v1` and `venter.tox-genotox.v1`.

## Changes

All changes in `tools/venter/commands/tox.py`.

### New validators

- `_validate_safety_pharm(doc)` — validates all required fields (compound_id,
  herg_ic50, herg_ic50_units), types, value sets (VALID_CONC_UNITS), and
  structured optional sub-objects (cardiovascular, respiratory, cns). Unknown
  fields within sub-objects are rejected via `_validate_sub_object()`.

- `_validate_genotox(doc)` — validates all required fields (compound_id, assays,
  battery_complete), assay-result objects via `_validate_assay()` (type, result,
  metabolic_activation with value-set checks), and the battery_complete
  cross-field constraint: if true, assays must include ames, one in vitro
  clastogenicity assay, and micronucleus_in_vivo. Incomplete battery with
  battery_complete=true raises Refusal (exit 9).

### Helpers

- `_validate_sub_object()` — generic validator for structured optional objects
  (cardiovascular/respiratory/cns). Checks dict type, rejects unknown keys,
  validates field types.

- `_validate_assay()` — validates individual assay-result objects within the
  genotox assays array.

- `_CARDIOVASCULAR_FIELDS`, `_RESPIRATORY_FIELDS`, `_CNS_FIELDS` — field specs
  for safety-pharm sub-objects.

- `_VALID_METABOLIC_ACTIVATION`, `_GENOTOX_ASSAY_OPTIONAL_FIELDS` — value sets
  and field specs for genotox assay validation.

### Refactored ingest

Extracted per-schema logic into three ingest helpers that share a common
interface: `(doc, input_path, sidecar) -> (normalised, record_id, suffix)`.

- `_ingest_repeat_dose()` — normalisation + sidecar notes for repeat-dose
- `_ingest_safety_pharm()` — normalisation + sidecar notes for safety-pharm
- `_ingest_genotox()` — normalisation + sidecar notes for genotox

`_INGEST_DISPATCH` maps schema tag to (validator, ingest_helper). `ingest_cmd`
now dispatches via this table, with shared code for file I/O, None-stripping,
artifact write, and sidecar write. The Phase 1 "will be supported in a future
release" Refusal is removed.

## Design decisions

- Sub-object validation uses a data-driven approach (`_validate_sub_object` with
  field-spec dicts) rather than per-field inline checks. This keeps the three
  sub-objects (cardiovascular, respiratory, cns) consistent and concise.

- The dispatch table pattern was chosen over a chain of if/elif blocks because
  it scales cleanly and makes the mapping from schema → (validator, handler)
  explicit and testable.

- `battery_complete` cross-field validation uses Refusal (exit 9) as specified
  in the design doc, since claiming a complete battery without providing the
  required assay types is a semantic refusal, not a structural error.
