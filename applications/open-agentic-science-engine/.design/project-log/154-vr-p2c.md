## Summary

Ported domain-specific features from the original viewer prototypes into
`brics-viewer.html` and `tournament-viewer.html`, following the port-into-shipped
pattern established in Phase 1.

## Changes

### brics-viewer.html

Replaced the generic JSON table renderer with a full BRICS decomposition viewer:

- **13-fragment BRICS catalog** with substring matching against SMILES strings
  (Amide, Phenyl, Pyridine, Thiazole, Sulfonamide, Piperazine, Methoxy, CF3,
  Hydroxyl-Ar, Nitrile, N-Methyl, Pyrrolidine, Br)
- **SMILES highlighting**: color-coded fragment substrings with overlap resolution
- **Fragment presence matrix**: compound x fragment grid with colored checkmarks
- **Tanimoto similarity matrix**: pairwise Jaccard index of fragment presence sets
- **Property comparison bar charts**: horizontal bars for docking_score, MW, LogP, TPSA
- **Score classification badges**: green (strong, < -8.0), yellow (moderate, -8.0 to -6.0),
  red (weak, > -6.0)
- **Sortable table columns**: click-to-sort headers with sort arrows

Preserved from shipped: `?file=` URL scheme (no `/raw/` prefix), `showError` error
handling, generic table fallback for non-BRICS data formats.

### tournament-viewer.html

Replaced the generic table renderer (which used `JSON.stringify` on nested objects)
with a domain-aware tournament viewer:

- **Nested field access**: properly destructures `idea.match.won/lost/win_rate`,
  `idea.attributes['Target Gene']`, `idea.prose.summary`
- **Tournament metadata header**: displays title, stage, state, ideas generated,
  highest ELO, date from top-level `data.tournament` and `data.stats` fields
- **Expandable detail rows**: click to expand and show hypothesis summary, category,
  review count
- **ELO color coding**: green (>= 95% of highest), amber (>= 85%), gray (below)
- **Win-rate color coding**: green (>= 60%), amber (>= 40%), red (below)
- **Column sorting**: clickable headers with sort arrows for ranking, ELO, win rate, gene

Preserved from shipped: `?file=` URL scheme, auto score-field detection, broader
data wrapper support (`data.hypotheses`, `data.results`, `data.rankings`, `data.ideas`),
medal-style rank coloring (gold/silver/bronze for top 3), `showError` error handling,
generic table fallback for non-tournament data.
