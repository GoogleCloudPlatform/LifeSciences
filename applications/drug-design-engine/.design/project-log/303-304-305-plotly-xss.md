# Fix Plotly XSS in Viewer Templates — Issues #303, #304, #305

**Date:** 2026-09-19
**Author:** dev-plotly-xss agent
**Branch:** scion/dev-plotly-xss (based on DDE)

## Summary

Three viewer HTML templates passed unsanitized user-controlled data into
Plotly.js chart configuration fields that render pseudo-HTML (axis labels,
chart titles, trace names, hovertemplates). Plotly.js parses hyperlink tags
in these string fields, enabling DOM-based XSS via `<a href="javascript:...">`.

## Changes

### contacts-viewer.html (#303)
- **xLabels** (line 126-128): Wrapped `r.res_name`, `r.res_num`, and `r.chain`
  with `escapeHtml()` in the axis label construction. Previously these were
  concatenated raw from JSON data.
- **yLabel** (line 184): Wrapped `name` (compound name derived from filename)
  with `escapeHtml()`. Previously passed raw to Plotly y-axis.

The `escapeHtml()` function already existed in this file (line 53). The chart
title and hover text were already escaped — these were the only two gaps.

### pae-viewer.html (#304)
- **Added `escapeHtml()` function** after `showError()` — this file had no
  HTML escaping function.
- **Chart title** (line 114): Wrapped `baseName` with `escapeHtml()` in the
  Plotly title text.
- **document.title** (line 51): Wrapped `baseName` with `escapeHtml()` for
  defense-in-depth.

### plddt-viewer.html (#305)
- **Added `escapeHtml()` function** after `showError()` — this file had no
  HTML escaping function.
- **Trace name** (line 121): Wrapped `chain` with `escapeHtml()` in the
  per-chain trace name field.
- **Hovertemplate** (line 122): Wrapped `chain` with `escapeHtml()` in the
  per-chain hovertemplate string.
